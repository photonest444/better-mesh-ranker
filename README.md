# Mesh Ranker — рейтинг класса МЭШ

Расширенная информация из рейтинга [school.mos.ru](https://school.mos.ru) в виде настоящего
приложения: **Windows и Linux на Electron**, **Android на Kotlin**, плюс веб-версия для
локального запуска. Одно общее ядро и один общий интерфейс — три разные платформы.

> Неофициальный клиент. Приложение только читает данные через открытые методы МЭШ
> и ничего не меняет в электронном дневнике.

## Что умеет

**Рейтинг класса (главная вкладка)**

- общий рейтинг и рейтинг по **нескольким предметам сразу** (мультивыбор чипами);
- таблица: место, Δ места за период, ученик, средний балл, предыдущий балл, Δ балла, полоса уровня, статус;
- KPI-плитки: моё место, мой средний балл с трендом, средний по классу, лидер класса, отрыв от лидера, «впереди/позади»;
- сводная **таблица сравнения предметов** (место, мой балл, средний по классу, отрыв, дельта);
- **гистограмма** распределения средних баллов класса;
- карточка ученика по клику: ближайшие соседи по рейтингу, полоса относительно максимума;
- снимок на любую дату (сегодня, −7/−30 дней, 1 сентября), экспорт в CSV, копирование текстом, печать.

**Предметы** — таблица со средним баллом, местом, трендом, признаком экзамена; клик открывает рейтинг по предмету.

**Оценки** — журнал за период с фильтрами (предмет, «только с оценкой»), гистограмма распределения,
итоги по предметам с медианой и «искрами» последних оценок.

**Домашние задания** — таблица со статусами, сроком сдачи, вложениями; карточка с полным текстом задания и копированием.

**Расписание** — день (таблица уроков) и **неделя** (пн–пт сеткой), переход по дням.

**Профиль** — переключение ученика (если детей несколько), состояние токена (маска, срок действия, хранилище),
экспорт профиля в JSON, выход с удалением токена.

**Настройки** — тема (авто/тёмная/светлая), строк на странице, компактные таблицы, гистограмма,
автообновление данных, автоматическое продление токена, сброс настроек, краткий отчёт о приватности.

## Вход в МЭШ: автоматически и один раз

Задача «войти и больше об этом не думать» решается так:

1. **Встроенное окно входа.** Кнопка «Войти через МЭШ» открывает страницу
   `/v2/token/refresh?roleId=1&subsystem=2` в отдельном окне (Electron) или WebView (Android).
   Токен **перехватывается автоматически** из адресной строки, `localStorage`, ответов
   fetch/XHR и текста страницы — скрипт-перехватчик ищет JWT или длинную строку.
2. **Ручная вставка.** Можно вставить токен (или скопированный текст страницы целиком) —
   ядро само вытащит токен, уберёт лишнее и покажет «токен распознан».
3. **Сохранение без повторного входа.** Токен лежит в защищённом хранилище платформы:
   Electron — `safeStorage` (DPAPI в Windows, libsecret/GNOME Keyring в Linux), Android —
   EncryptedSharedPreferences (ключ в Android Keystore). В интерфейсе показывается только маска.
4. **Автоматическое продление.** При ответе `401` ядро один раз вызывает
   `/v2/token/refresh` с текущим токеном, сохраняет новый и **повторяет исходный запрос** —
   для пользователя это незаметно. На Android то же самое делает фоновая задача WorkManager
   каждые 12 часов; в Electron — главный процесс.
5. **Демо-режим** позволяет посмотреть интерфейс без аккаунта МЭШ: данные генерируются
   локально тем же ядром, что и в тестах.

## Структура репозитория

```
ranker.py                исходный CLI-скрипт (остаётся как есть)
shared/                  общий код для всех платформ
  core/mesh-core.js        протокол МЭШ: адреса, заголовки, разбор, автообновление токена
  core/lib/                утилиты, статистика, форматирование, таблицы
  ui/                      интерфейс: вкладки, таблицы, экран входа, стили (без фреймворков)
desktop/                 Electron (Windows, Linux)
  src/main/                главный процесс: IPC, окна, хранилище токена, окно входа
  src/preload/             мост contextBridge (window.meshDesktop)
  src/renderer/, src/core/ собираются скриптом npm run sync из shared/ (в git не нужны)
  build/icon.png           иконка приложения (electron-builder делает из неё .ico)
android/                 Kotlin-приложение
  app/src/main/java/ru/meshrating/app/
    MeshCore.kt              протокол МЭШ (совместим с shared/core/mesh-core.js)
    MeshClient.kt            HTTP, таймауты, автообновление токена
    MeshApi.kt               методы приложения (контракт с интерфейсом)
    MeshAndroidBridge.kt     мост WebView → Kotlin (window.MeshNative)
    MainActivity.kt          WebView с общим интерфейсом + меню
    MeshLoginActivity.kt     окно входа: перехват токена
    SessionStore.kt          EncryptedSharedPreferences (Android Keystore)
    TokenRefreshWorker.kt    фоновое продление сессии
    DemoMeshServer.kt        локальный демо-МЭШ
  app/src/test/            JVM-тесты ядра и клиента (без эмулятора)
tools/                   mock-mesh-server.js (мок МЭШ), preview-server.js (веб-версия), smoke-preview.js
tests/                   модульные тесты ядра (node:test)
docs/                    API-CONTRACT.md, BUILD.md
.github/workflows/       CI, сборка Windows/Linux, сборка APK
```

## Быстрый старт

### Веб-версия (самый быстрый способ посмотреть)

```bash
node tools/preview-server.js --demo        # http://localhost:8787, демо-данные
node tools/preview-server.js               # боевой режим: вход по токену МЭШ
```

### Desktop (Windows / Linux)

```bash
cd desktop
npm install
npm start          # запуск приложения
npm run demo       # запуск со встроенным демо-сервером МЭШ
npm run dist:win   # установщик NSIS + portable (Windows)
npm run dist:linux # AppImage + .deb (Linux)
```

### Android

```bash
cd android
./gradlew assembleDebug      # APK для проверки
./gradlew test               # JVM-тесты ядра (без эмулятора)
./gradlew assembleRelease    # релизная сборка (подпись — см. docs/BUILD.md)
```

Готовые сборки также собираются автоматически: см. `docs/BUILD.md` и раздел
«CI/CD» ниже.

## Как это собирается в CI

| Workflow | Что делает |
| --- | --- |
| `.github/workflows/ci.yml` | проверка синтаксиса, `node --test tests/`, дымовой тест полного пути пользователя, проверка main-процесса Electron, поиск случайно закоммиченных токенов |
| `.github/workflows/desktop.yml` | сборка Windows (NSIS + portable) и Linux (AppImage + deb), артефакты + публикация в релиз по тегу `v*` |
| `.github/workflows/android.yml` | JVM-тесты ядра, `assembleDebug`, `assembleRelease`, артефакты APK |

По тегу вида `v1.0.0` все артефакты автоматически попадают в GitHub Release.

## Безопасность и приватность

- приложение работает **только на чтение**;
- токен хранится в защищённом хранилище ОС/устройства, в интерфейсе — только маска;
- в репозиторий не попадают токены и кэши (`.gitignore`, отдельная проверка в CI);
- резервное копирование Android исключает файлы сессии (`data_extraction_rules.xml`);
- никакой аналитики и передачи данных третьим лицам.

## Использование CLI-скрипта

Исходный скрипт никуда не делся и умеет то же, что раньше:

```bash
pip install requests
python3 ranker.py
```

Кэш имён `~/.better-mesh-ranker/users_cache.json` (если он есть) подхватывается
desktop-версией автоматически — рейтинг открывается мгновенно.
